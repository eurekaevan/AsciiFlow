# Stage 5.3A — color metadata and HDR classification

Status on 2026-09-26: **Stage 5.3A SEALED on the measured Intel Arc stack**.
The original Stage 5.2C-3 10-bit input artifact and SHA-256 were not retained;
its two output hashes remain unverified historical references, not PASS
results. A new, checked-in, fully reproducible canonical 10-bit baseline v1
replaces them as the current regression gate. See the
[hardware closure report](stage5.3a-hardware-closure.md). Stage 5.3B is now
justified but has not begun.

## Audit and implementation

Before this change, Core had coarse color enums but no raw-versus-effective
model. The decoder merged frame color only for 10-bit, rejected PQ/HLG or
BT.2020 with a combined message, rejected static HDR side data by presence,
and did not check 8-bit color changes frame-to-frame. NV12 output was always
tagged BT.709 limited. P010 could retain a full-range input tag even though
CPU/Vulkan ASCII output uses limited-range black/white code values.
The existing software scaler used ITU601 coefficients for an unspecified
8-bit input matrix; this compatibility assumption is preserved, rather than
silently changing pixels to BT.709 coefficients. Explicit 8-bit BT.601/170M
input remains a software-decode color-normalization path; hardware direct
decode is excluded because it has no equivalent gamut/matrix conversion.

Core now keeps raw stream/frame facts, a resolved interpretation with field
provenance, SDR/PQ/HLG/Unknown/Conflicting classification, and a separate
support result. Planner legality consumes that result. Media maps FFmpeg
primaries, transfer, matrix and range independently, parses mastering/CLL
side data as checked exact rationals/integers, and validates semantic stability
after the first decoded frame. PQ, HLG and wide-gamut SDR produce distinct
errors before target mutation. The 8-bit unspecified-field compatibility
default is explicit; 10-bit unknown fields fail closed. Full-range output is
now rejected until range-aware pixel rendering is qualified. No shader,
Vulkan, interop, codec, or production HDR processing was added. See
[color-semantics.md](color-semantics.md) for the exact policy and source
priority.

## Fixtures and results

The checked-in 64×64, 36-frame fixtures are generated by
[`tests/fixtures/codecs/generate.sh`](../tests/fixtures/codecs/generate.sh)
with FFmpeg 8.1.2; versions, commands and SHA-256 are in the fixture README
and `SHA256SUMS`. The seven old hashes stayed unchanged. Eight new files cover
HEVC full-range BT.709, BT.2020 SDR, HLG, unspecified color, PQ with
contradictory BT.709 tags, PQ with mastering+CLL, AV1 PQ, and HEVC Main8
BT.601/170M. These 15 small files
decode 36 frames; new stream and first-frame tags agree. The PQ static fixture
exposes mastering max luminance 1000 cd/m² and MaxCLL/MaxFALL 1000/400.
These are deterministic metadata samples, **not calibrated HDR imagery**.

Software integration tests classify HEVC PQ/HLG, AV1 PQ, BT.2020 SDR,
unknown and contradictory tags; PQ classification works with and without
static metadata. BT.709 8-bit/10-bit decoder regressions and the legacy
BT.601→BT.709 software-normalization case pass. Core tests
cover partial/unspecified signals, default provenance, stream/frame conflict,
range, invalid mastering values and synthetic mid-stream SDR→PQ rejection.
CLI tests confirm unsupported color inputs leave an existing target untouched
and leave no staging file. An opt-in HEVC/AV1 Main10 software-vs-VAAPI color
parity test is present and passed on the Intel render node; see the hardware
closure report for raw-source observations.
The HEVC and AV1 software fixtures agree on resolved primaries, transfer,
matrix, range and SDR/PQ class. Their chroma-location signals differ (HEVC
left, AV1 unspecified), so this comparison does not claim complete production
AV1 input qualification from the small synthetic file.
The release-mode manual resolution sanity test measured about 35 ns per call
over one million calls on this host, far below 1 ms. Resolution is performed
at first-frame qualification; later frames compare compact resolved fields and
static metadata for stability rather than repeating capability planning.

The current mapping's explicit priority is decoded-frame value over stream
value when the latter is unspecified; contradictory explicit values fail.
Stream fields come from the decoder context populated from codec parameters,
while static coded side data comes from codec parameters. The distinct raw
codec-parameter and decoder-context field sets are not separately retained.
The real-device observations found no difference requiring that model extension;
the general provenance limitation remains documented.

Final local validation: `cargo build --release --workspace`, both ordinary
and `encode-characterization` workspace test suites, both all-targets Clippy
variants with `-D warnings`, `cargo fmt --all --check`, `git diff --check`,
fixture SHA-256 verification and `spirv-val --target-env vulkan1.3` on all
133 generated modules passed. The subsequent Intel pass reran these checks
and probed actual output from all five production codecs.

## Canonical 10-bit baseline and historical limitation

The separately pinned FFmpeg 8.1.3 generator in
`tests/fixtures/codecs/generate-10bit-baseline.sh` created the checked-in
1920×1080/300-frame HEVC Main10 BT.709 limited input, SHA-256
`df69c98ca6592b08c6bc34127b2bb5cf4125c759fd852b830e5426d5818fccda`.
Three independent generations matched byte-for-byte; 700,261,022 of
933,120,000 decoded 10-bit samples had nonzero low two bits. With the same
input and fixed Intel full-GPU config, three HEVC Main10 production outputs
all hashed
`07f231ab49eebd54cc0e85012f7dd12e424f580d17005bc20028b458168323fe`;
three AV1 10-bit outputs all hashed
`2ab82984f690ea3fe5472c874dfce7cc474f7c46266f5cd86ed8deee20b36fda`.
Both decoded cleanly to 300 frames at 50 fps with Main10/10-bit 4:2:0 and
BT.709 limited metadata; 300-frame pre-encode P010 parity passed for both.
The fixture [README](../tests/fixtures/codecs/README.md) and
[testing guide](testing.md) preserve the generator/tool identity, exact
commands and future regression policy.

The old Stage 5.2C-3 hashes are retained verbatim in the hardware report,
marked **historical reference only; input identity unrecoverable; not used as
the current regression gate**. No equality between old and new hashes is
claimed. This is a reconstructed replacement baseline, not a recovery.

The fixed limited-range rendering semantics are a known boundary: full-range
SDR must remain rejected until a later pixel-semantics stage qualifies it.
HDR detection does not grant HDR processing support. Stage 5.3B was not
implemented in this closure pass.
